# AI Expanded Contract

## 目标

把已验收的 `source-faithful.md` 重组为一份可直接收藏和学习的 Markdown。它不是视频逐段摘要，也不是视频原话的注释版。

## 输入边界

- `source-faithful.md` 是冻结输入：不得改写、覆盖或以它未出现的操作冒充视频事实。
- 用户用自然语言说明学习目标、已有基础、重点与排除范围；没有说明时，目标是“讲明白，并让我能马上使用，不啰嗦”。
- 先在内部确定单元顺序，再输出成结构化草稿；不反复重写全文。

## 最低 Token 的核查顺序

1. 只读取一次完整 source-faithful，提取精简的学习结构和待核查主张。每项主张只保留原子结论、核查原因与优先级；不逐句拆分，不写读者 Markdown。
2. 去重后，使用 `Agent Reach` 只搜索待核查主张。禁止把完整 source-faithful、原始字幕、截图或整篇草稿发送给联网检索。
3. 将每项结果压缩为“可采用的结论 + 必要的纠正说明 + 内部来源”。随后以学习结构和核查结果填充最终草稿，不再次读取完整 source-faithful。
4. 读者 Markdown 只由这份最终草稿写出；同一段视频内容不得因为核查再被第二次完整改写。

## 内容规则

- 每个单元按实际需要选用 `concept`、`method`、`operation` 或 `fact`；不要为凑模板重复“解释、类比、测验”。
- 概念要给出一句本质和大白话解释；方法要给出使用时机、判断逻辑和最小流程；操作要保留目标、步骤与检查点；事实只保留结论或记忆线索。
- 只在确有帮助时添加例子、边界、易错点、对比、记忆提示和 1 至 3 项应用练习。
- 纠正、筛选和扩展必须服务于学习目标，不能堆砌背景、重复原文或制造看似完整的空章节。

## 核查规则

- 默认只核查明显可疑、有风险、时效性强、相互矛盾，或用户明确要求核查的事实；作者的偏好与创作选择不当作错误。
- 私人教学视频中的可迁移专业知识默认进入候选清单，例如专业定义、通用方法论、软件功能事实和被讲成普遍规律的结论。视频实际演示过的操作仍由 source-faithful 保留，不必重复搜索。
- 用户说“不要联网”时不核查。用户说“重点核查 X”时，把 X 作为 targeted 范围；其他自动核查仍按必要性决定。
- 核查成功时，内部 `audit.verification` 必须记录来源；网络失败或证据不足时标记 `unresolved`，不得声称已验证。

## 输出边界

- 只输出 Markdown：标题、`30 秒掌握`、动态学习单元，以及必要时的 `立即应用`。
- 不输出时间戳、截图、原始字幕、来源链接、核查审计、JSON 字段，也不输出“视频说 / AI 扩展”的对照标签。
- 不生成 HTML。
