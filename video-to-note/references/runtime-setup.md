# 运行环境匹配与项目内安装

仅在首次环境检查、缺少 `task-runtime.ps1`，或检查结果为 `missing_tools` 时读取本文件。

## 本机环境自动匹配

运行 `scripts/check_environment.ps1`。检查器按以下顺序解析每项工具：

1. `VIDEO_NOTE_*` 显式绝对路径。
2. 当前项目的 `.video-note-runtime`。
3. 当前进程 `PATH`。
4. Windows 常见安装目录，包括 Python 用户安装目录、WinGet 的 FFmpeg 包目录以及 Edge/Chrome 默认目录。

检查结果为 `ok` 时，直接复用报告中的绝对路径继续任务，不安装、不下载。可把这些路径写入当前项目的 `task-runtime.ps1`，以便后续运行保持一致。

显式路径存在但指向无效文件时，这是配置错误。先修正该路径，不得静默切换到另一个版本。

## 安装前去重门禁

即使检查器返回 `missing_tools`，也必须先完成以下盘点，不能直接下载：

1. 若存在 `task-runtime.ps1`，在当前 PowerShell 进程中点源它，并列出所有 `VIDEO_NOTE_*` 显式路径；只读取文件或用 `&` 启动子进程都不会保留环境变量。
2. 逐项验证已有显式路径。文件存在且对应工具能正常输出版本时，判定为已安装并直接复用。
3. 再检查当前项目 `.video-note-runtime`、当前 `PATH`、Windows 常见安装目录和包管理器目录，确认是否已有同一工具的其他副本。
4. 检查正在运行的安装或下载进程，以及 `.retry`、`.part`、空解压目录、损坏的压缩包等残留。
5. 记录每个候选的来源、版本和绝对路径；只有全部候选都无效时才能进入安装流程。

已有显式路径可用时，禁止再次下载或安装。超时、权限错误或目录枚举失败不等于工具缺失；必须修正检查条件后重新验证。发现残留时只清理已确认损坏且未被配置引用的文件，不得删除可用的系统安装。任何时候同一工具只允许一个安装流程，检查未完成前不得启动第二次下载或安装。

## 缺失时的处理

检查结果为 `missing_tools` 时：

1. 向用户列出 `missing_tools`，说明将使用 `workspace_runtime_dir`。
2. 先征得用户授权，再下载缺失依赖。
3. Python 包安装到 `<workspace>/.video-note-runtime/venv`。
4. 便携版 FFmpeg 解压到 `<workspace>/.video-note-runtime`。
5. 生成或更新 `<workspace>/task-runtime.ps1`，只记录已验证的绝对路径。
6. 重新运行环境检查；通过后才能初始化视频请求。

不得全局安装，不得默认调用 `winget install`，不得修改系统 `PATH`，不得把依赖写入其他项目。浏览器通常只复用本机已有版本，不因为视频处理任务单独安装浏览器。

安装或下载超时后，先检查残留进程、目标文件和虚拟环境模块，不得直接启动第二个安装进程。

## 转写模型下载例外

首次转写可能需要下载 Whisper 模型。用户启动视频笔记任务即视为对当前项目模型下载的持续授权：本地没有所需模型、缓存不完整或上次网络超时时，直接下载或续传到 `<workspace>/.video-note-runtime/cache/whisper`，无需再次询问。默认 `turbo` 模型约 1.5 GB。

模型下载超时后保留缓存，停止当前命令并报告网络错误；下次运行自动使用同一目录继续，不得启动并行下载。该例外不得扩展到 Python、FFmpeg、ffprobe、yt-dlp、浏览器或其他依赖，它们仍必须先征得用户授权。
